# BRIEF — OnCue · 群聊试映室

（官方 script-app 流程第 1 步产物：每个画面与动作一行，每个能力给出理由；不放入发布包。本文件描述当前行为与验证目标，不是本轮运行通过报告。）

## 目的

在群聊里说话之前先私下排练。用户写下想说的话，应用读取**用户授权房间**的最近消息作为事实线索，
请设备上的助手（octos）就此生成**三条不同方向的假设下一幕**，用户逐句播放查看，
挑一条改动后存成草稿（A/B 两版），再自行决定要不要发。**应用自身不发送任何消息。**

| # | 画面 | 动作 | 用到的能力 |
| --- | --- | --- | --- |

## 数据来源

- **真实**：宿主授权后，`matrix.read_messages` 以 `limit: 12` 请求最近文本消息，`matrix.room_info` 返回房间名；不保证每次恰有 12 条。
- **模型输入**：所有已载入消息的编号、`sender`、`body` 与 trial 台词，而非仅当前可见消息或最终摘录；由宿主配置的模型处理，可能离开设备并产生用量。
- **助手产出**：原消息编号选择、三条假设对白和建议；摘录正文由应用按编号取回，非助手撰写事实摘要。
- **虚构**：内置样例「国庆搭子局」的预设消息与预设路线，不是真实模型回合。
- **本地**：草稿及 A/B 存于账号 + 应用级 jail，不按房间隔离；清空编辑框不删除持久文件。详见[隐私说明](<PRIVACY.md>)。

## 状态

- 空：没有路线时不崩溃并给出提示。
- 失败：权限被拒 / 无消息 / 助手不可用 / 回合失败 / 响应过期，均有状态行反馈。
- 重启：草稿 A/B 由 `storage` 持久化。

## 能力与理由（每一个都对应上面的画面）

| 能力 | 理由 |
| --- | --- |
| `storage` | 画面 9：草稿 A/B 需要落盘 |
| `matrix.room_info` | 画面 2：显示房间名（房名为空时显示「已授权群聊」，不回落到房间 ID） |
| `matrix.read_messages` | 画面 2、3：读取并逐条展示授权房间的消息 |
| `octos.session.open` | 画面 4：打开本应用自己的助手会话 |
| `octos.turn.start` | 画面 4：请助手生成三条假设路线 |
| `octos.turn.interrupt` | 画面 5：用户可中断进行中的回合 |

## 明确不申请

- `net` / `images` / `web`：应用不直接访问网络主机（`network.hosts` 为空）；宿主 Matrix/模型服务可能联网，不能据此宣称数据不出设备。
- `prompt`、`llm`、`news`、`glance`、`research`、`crawl`、`clipboard`、`ledger.read`：当前产品不需要；不把 `glance` 误说成所有商店应用都不可用。
- 相机 / 麦克风 / 位置 / 相册 / 邮件与 Matrix 发送能力：与当前私人排练功能无关。
