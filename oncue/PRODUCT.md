# 群聊试映室：产品与开发边界

## 一句话

为聊天加一个私人排练舞台：一句尚未发出的消息，可以展开三个不同的下一幕。

## 演示现场

虚构国庆出游群：有人 12 点后才能走，有人要当天返回、预算约 300，
另一人对目的地没有偏好。

试着说“明早 9 点走，住一晚”。第一条路线呈现时间与返程岔口；
第二条把拍板改成两个可回答的选项；第三条提出半日旅行盲盒。
改成“中午走，当天回”，再试映，第一条路线随之改变。

观众看到的变化来自改台词、换路线、留草稿的操作。
原始消息、假设回应与新的提议在界面中保持可辨认。

## Rinx 原生 v0.1 源码中的流程（尚待宿主验证）

1. 样例舞台，让第一次打开应用的人立刻知道怎么玩。
2. 读取本次授权群聊最近 12 条文本消息，显示编号。
3. 私下试一句话，Agent 生成三条假设路线。
4. 选择、编辑、保留一份本地草稿。
5. 反馈权限拒绝、无消息、无模型、模型失败、协议不完整和过期响应等状态。

## 服务器体验版 v0.2 已实现

- 无需图形桌面的 Python HTTP 服务，浏览器打开体验。
- 三组虚构现场：国庆出游、周五聚餐、周末创作。
- 手动导入聊天片段；本地规则与真实 MiniMax 试映分别标明。
- 剧情存档：保存并恢复一个现场与台词，对照最近两版的三条路线。
- 草稿保存、清空、导出；带原消息和假设标签的剧本导出。
- 每条来源摘录逐字核对；部分时间、过夜提议和新增费用数字显示待确认提示。
- 当前浏览器内的存档和草稿由用户主动保存，服务器不保存会话内容。

此版本通过手动输入取材，没有接入真实 Matrix 消息。

## 候选后续玩法

- 角色卡：整理消息中明确说出的约束与偏好。
- 共同出题：用户确认后把小游戏提议带回群里，由真实群友选择玩法。
- 双人接力：两个人各写一句，从真实回复推进下一幕。

这些是后续候选，当前版本没有声称实现。

## Rinx v0.1 模型输出协议

七个非空文本块，用单独一行 @@@ 分隔：
现场摘要、A 假设对白与依据、A 草稿、B 假设对白与依据、B 草稿、
C 假设对白与依据、C 草稿。

解析器拒绝块数错误和空块。路线内容仍需人对照原消息判断。
引用编号目前由模型按提示生成，尚未建立自动逐条事实核验。

## Rinx 原生接入边界

- 群聊数据由 Rinx 提供，Matrix 密码留在宿主中。
- 模型与凭证由宿主提供，API key 不进入应用包。
- 模型试映时，选定消息会进入用户配置的模型上下文。
- 草稿使用 Rinx 为当前账号和应用分配的本地存储。
- 本版本没有消息发送能力。

## 服务器模型输出

使用 OpenAI 兼容的 MiniMax Chat Completions 接口，单次调用输出 JSON。
固定三条路线，每条包括简短路线名、假设对白、建议台词与来源编号及逐字摘录。
协议不完整、引用编号不存在或摘录对不上原消息时，返回明确错误，不自动改用本地演示。
逐字摘录检查和有限的词语检查无法证明整个剧情符合事实，使用者仍需对照原消息。

## 用户协助

开发已在当前环境推进，真实 MiniMax 凭证已用于样例联调，凭证不进入交付。
服务器体验版只需 Python，可通过已有 SSH 转发或 HTTPS 入口用浏览器操作。
下一阶段如果需要读取本人 Matrix 会话，由本人在实际 Rinx 宿主授权测试群；
该步骤不是服务器版开发的前置条件。
