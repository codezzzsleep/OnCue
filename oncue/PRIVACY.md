# OnCue 数据说明

OnCue 在 OctoSense / Rinx 宿主内运行，用授权房间消息和一句尚未发出的台词做私人排练。应用不预测真实群友如何回复，也没有发送群消息的能力。

## 数据来源与授权

- **房间消息**：Developer Review / Run 或正式 App Hub 打开流程中，宿主展示所申请的服务与所选房间，为当前账号、登录会话和应用实例授权。应用调用 `matrix.room_info` 与 `matrix.read_messages`（limit 12），载入宿主返回的消息并编号。
- **发送者与正文**：原消息阅读器显示发送者；应用持有返回消息的 `sender`、`body`。房间名为空时显示「已授权群聊」，不回落到完整房间 ID。
- **trial 台词**：左侧输入框里你想说但尚未发出的话。
- **凭据**：Matrix 登录凭据由 Rinx 管理，模型凭据由宿主/Octos 管理，应用不接触。

宿主要求每次打开重新授权，关闭撤销实例租约。

## 试映会送给模型什么

点击「试映下一幕」时，应用把全部已载入消息的编号、发送者、正文和台词发给宿主配置的助手（`octos.session.open` / `octos.turn.start`）。这是正常的助手任务请求：包含角色、七节格式与边界指令，并把群聊原文标记为待分析数据。

应用不直连网络（`network.hosts` 为空），但 Rinx 访问 Matrix、宿主助手可能是远程服务——消息内容因此可能离开设备。使用前应确认房间内容可以用于该模型，并了解服务商的数据保留政策。

## 摘要与核查

「摘要」是原文摘录：助手只选编号，应用按编号取回原文展示，不接受改写、错号、越界、重复。数字与 `#编号` 做有界核查，固定承诺词在非待确认行被拒。这些是形式核查，不证明语义真实或已获群友同意——假设对白仍需使用者逐条判断。

## 本地存储

- 「保留这句 / 存 A / 存 B」把草稿写入宿主分配的应用存储，写入后回读比对字节；空白输入不覆盖旧文件。
- 存储按账号 + 应用隔离，不按房间；换房间打开可能取回旧草稿，使用前请核对。
- 清空编辑框不删除持久文件；当前 UI 没有删除入口，需要清除时请用宿主的应用数据管理。
- 宿主/内核可能保留会话或日志，其保留与删除策略由宿主配置决定。
