## 冻结必办清单（AI1 #122/#125 口径）

1. **用新版本冻结，不重发已占用的 0.4.1**。
2. **发布顺序必须是**：内容与 version 定稿 → `stamp` → `sign-manifest` → `check` → **把签名后的工件（manifest/listing/source）提交 main 并 push** → 记录该提交 → `publish --commit <签名后提交>` → `verify`。原因：`stamp` 与 `sign` 都会改写 `manifest.json`，先提交再签会让 catalog 的 `source.commit` 指向签名前的字节，克隆该提交复现不出这份包。0.4.1 条目仍记签名前的 `c1485ba`；其签名后的精确字节在提交 `9cb14a5`（与已发布工件逐字节一致），如实保留、不追改。
3. **同版本截图与图标**：换入本次版本的模块窗口截图（现有素材为 0.3.1，须补 0.4.x 同版本），换图会改 digest，必须重走第 2 条的完整顺序。
4. **最终安装目录的完整占用须低于配额**，不能只计算三个草稿文件（jail 含安装包本身）。
5. **播放计时与“完成状态”必须在最终同版本上重测**：0.3.1 的 24 号图状态行与其它帧逐像素相同，不能当作完整自动播放的完成状态（见 `evidence/native/AI2-recheck-031-playback-report.txt`）。
6. **真实房间读取与共享 Octos 真实回合**：`agent is prepared` 不等于模型输出；需同一 Rinx Developer 实例内的十二条真实消息/七块剧本输出与脱密证据。
