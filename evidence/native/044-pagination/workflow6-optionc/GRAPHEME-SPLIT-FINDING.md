# 发现：方案C（`msg_rows=1`）下页边界会**切断字素簇**，emoji 显示为破碎字形

**限定**：产品代码问题；在合入后的包（`cue_page_cols=16` / `cue_page_rows=3` / `cue_msg_rows=1`）上复现。
**不是宿主/Rinx 的问题，与任何补丁环境无关。**

## 算法层定位（按合入后的常量 `cols=16, rows=1` 精确复刻 `cue_paginate`）

对 8 个夹具检查"某页的**第一个字符**是否为续接字符"（续接 = 组合记号 Mn/Mc/Me、变体选择符、ZWJ/ZWNJ、
肤色修饰符 U+1F3FB..FF、区域指示符 U+1F1E6..FF）。若是，则说明**上一页把字素簇切开了**：

| 夹具 | 页数 | 首字符是续接的页数 | 例 |
| --- | --- | --- | --- |
| 01–05、07、08 | 34/21/27/46/51/28/46 | **0** | — |
| **06-emoji-combining** | 32 | **2** | `p4: U+1F3FD`（肤色修饰符）、`p5: U+1F1F3`（区域指示符） |

## 像素确证（真实 card-host，412×892）

- `shots/grapheme-split-p4.png` —— **第 4 页末尾**是一个孤立的 **`🇺`**（U+1F1FA）
- `shots/grapheme-split-p5.png` —— **第 5 页开头**是一个孤立的 **`N`**（U+1F1F3）

两者合起来就是 **`🇺🇳`（联合国旗）**，被页边界**拆成两半**，于是用户看到的是
"半个旗帜 + 一个字母 N"，而不是一面旗。算法预测的 `p5: U+1F1F3` 与像素观测**完全对应**。

## 影响与边界（不夸大）

- **字符没有丢失**：第 ③ 项的应用自证 `equal=true` 仍成立（码点级拼接无损），
  所以这是**显示层**问题：**页边界处的字素簇被切开，emoji/旗帜显示为破碎字形**。
- **只影响含续接字符的文本**（组合 emoji、肤色修饰符、旗帜、ZWJ 序列）；
  纯中文/英文/空格/换行夹具**全部 0 处切断**。
- 方案C 把 `msg_rows` 从 4 降到 1，**每页只有 1 行（16 列）**，页边界密度大幅提高，
  因此比旧参数**更容易**碰到字素簇切断 —— 这是保守分页带来的一处代价。

## 建议修法（未擅自实施）

在 `cue_paginate` 的折页判断处加一条：**不要把续接字符推到下一页**
（即遇到续接字符时强制留在当前页，允许该页多占 1 列）。
这会改动产品代码与 bundle 摘要，**等指示后再改、再验证、再 stamp**。

## 修复方案已在探针副本上**验证通过**（尚未应用到仓库包）

**改法**：给 `cue_paginate` 加 `cue_is_continuation(c)`；折页时若当前字符是续接字符则不折页。

**验证结果**
| 层 | 修复前 | 修复后 |
| --- | --- | --- |
| 算法层（8 夹具合计"页首为续接字符"的页数） | **2** | **0** |
| 算法层（夹具 06 页数） | 32 | 32（不变） |
| 像素层（412×892 第 4 页末尾） | 孤立的 `🇺` | **完整的 `🇺🇳`**（见 `shots/grapheme-fix-p4-intact-flag.png`） |

**⚠️ 实现时踩到并必须记住的两个 Splash 语法限制**（否则整个脚本会静默失败、界面变空）：
1. **不支持 `0x` 十六进制字面量**：`0x1AB0` 被解析成 `0x1` + 变量 `AB0`，
   日志报 `variable AB0 not found in scope`。**必须写十进制**。
   （这也解释了为什么现有代码里全是 `9472`、`126976` 这样的十进制。）
2. **不支持"空代码块 + else"**：`if c { } else if … {` 会报
   `assign target is not an identifier`。改用 `let wrap = …; if c { wrap = false }; if wrap { … }`。
