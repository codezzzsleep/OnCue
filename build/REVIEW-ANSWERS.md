# 应用自查七问 — OnCue 0.5.1 未签名审阅版

以下是源码及实际证据自查，不是App Hub官方审核结论。实际运行范围集中在[验证记录](../oncue/VERIFICATION.md)。

## 1. 名称与描述是否符合实际用途？

用途是私人群聊排练：明确表达目标，三建议速览，手工编辑或提出修订要求，候选对照后应用，按房间保存主稿/A/B。假设对白可另行播放。应用不申请或调用Matrix发送服务。样例为本地规则和固定修订模板，不冒充真实模型。

## 2. 平台与分类是否合适？

仅声明Linux；当前本地验证环境为Linux aarch64。分类productivity、年龄等级all。其他平台及当前真实Rinx/模型流程是否完成，以验证记录为准。

## 3. 能力是否有对应功能？

| 能力 | 功能 |
|---|---|
| `storage` | 房间草稿、A/B、回读、迁移和删除 |
| `matrix.room_info` | 房间名称及稳定身份 |
| `matrix.read_messages` | 授权房间最近最多12条文本 |
| `octos.session.open` | 打开宿主模型上下文 |
| `octos.turn.start` | G2三路线生成或R1单稿修订 |
| `octos.turn.interrupt` | 停止及90秒期限中断请求 |

没有直接网络主机或发送权限。模型请求包含选定消息编号/正文、台词、目标和补充条件；R1另含原稿与修订要求。模型许可与房间读取分开，范围改变后须重新允许。

## 4. 是否有误导性界面？

不收集密码、令牌或验证码，不提供支付。生成候选、应用到编辑框、保存、删除分开；人工编辑不继承候选检查状态。保存需实际写入和逐字回读；损坏或不确定时停写。没有把“原文存在”标成“事实正确”。

## 5. 是否含助手指令？

有。G2与R1提示词规定结构、来源和假设边界。用户消息以数据形式放入请求；这不是完整提示注入防护。宿主控制模型历史和工具，应用不承诺session.open清空历史或工具绝对不可用。

## 6. 是否冒犯或针对私人个体？

内置场景及回应虚构；不预测真人心理，不冒充群友。发送者标签不进入模型请求，但正文仍可能识别人，使用者须有权用于该模型。

## 7. 建议审核路线？

**human-review。** 当前为未签名PR审阅包，不是最终发布。重点核对目标/修订的实际效果、宿主数据范围、重新打开与删除、失败时草稿是否保留。队外用户试用和真实模型质量不能用受控VM测试代替。

新草稿按账号/房间隔离，最多10个记录、每稿8000字节、文件512 KiB；旧版主稿/A/B手动复制与独立删除。没有自动备份、跨进程锁或崩溃原子性保证。第三方模型历史不属于本地删除范围。完整说明见[数据说明](../oncue/PRIVACY.md)。
