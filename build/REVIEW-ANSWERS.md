# 应用自查七问 — OnCue 0.5.4

以下是源码及实际证据自查，不是App Hub官方审核结论。实际运行范围集中在[验证记录](../oncue/VERIFICATION.md)。

## 1. 名称与描述是否符合实际用途？

用途是私人群聊排练：明确表达目标，三建议速览，手工编辑或提出修订要求，候选对照后应用，按房间保存主稿/A/B。假设对白可另行播放。草稿确认后**可以发到群里**：发送是两步确认（「发到群里」核对完整正文后点「确认发送」，60秒内有效），发送后回读最近30条核验本人同文消息。样例舞台为本地固定内容，不冒充真实模型，且不能发送。

## 2. 平台与分类是否合适？

仅声明Linux；当前本地验证环境为Linux x86_64。分类productivity、年龄等级all。其他平台及商店流程是否完成，以验证记录为准。

## 3. 能力是否有对应功能？

| 能力 | 功能 |
|---|---|
| `storage` | 房间草稿、A/B、回读、迁移和删除 |
| `matrix.room_info` | 房间名称及稳定身份 |
| `matrix.read_messages` | 授权房间最近最多12条文本；发送前最终核对与发送后回读；看反响时重读最近30条并列出已核实那条之后的新回复 |
| `matrix.account_info` | 发送确认前核验当前账号身份 |
| `matrix.send_message` | 两步确认后发送草稿正文，错误按宿主原话归因 |
| `octos.session.open` | 打开宿主模型上下文 |
| `octos.turn.start` | G2三路线生成（可带【推荐】）、R1单稿修订、F1反响对照（仅在有新回复且允许有效时） |
| `octos.turn.interrupt` | 停止及150秒期限中断请求 |

没有直接网络主机。模型请求包含选定消息编号/正文、台词、目标和补充条件；R1另含原稿与修订要求；F1反响对照另含已发送那句、试映预想（如有）与新回复正文（不含发送者标签）。模型许可与房间读取分开，范围改变后须重新允许；撤回、授权过期或账号切换后看反响只列原话、不调用模型。发送不自动重试；回读不能确认时提示"是否已发送尚不能确认"，并警告重复发送风险。

## 4. 是否有误导性界面？

不收集密码、令牌或验证码，不提供支付。生成候选、应用到编辑框、保存、发送确认分开；人工编辑不继承候选检查状态。保存需实际写入和逐字回读；损坏或不确定时停写。发送确认页展示完整正文与字数（上限4096码点），「确认发送」唯一实例贴在确认区完整正文旁，草稿或上下文变化会使确认失效。承诺句式（"已经/都/全/大家/已"+结果动词、"订好了/就这么定/没意见了"等）除固定词表外逐条识别，并须逐字出现在勾选原文、台词或补充边界（看反响时还有回复原文）里才放行，否定与"待确认：是否…？"问句不算。数字只认本路线依据列出的消息加用户输入；单条路线不合格只丢该条并在原位置写明原因，三条全不过才自动重试一次。没有把"原文存在"标成"事实正确"。

## 5. 是否含助手指令？

有。G2、R1与F1提示词规定结构、来源和假设边界。用户消息以数据形式放入请求；这不是完整提示注入防护。宿主控制模型历史和工具，应用不承诺session.open清空历史或工具绝对不可用。

## 6. 是否冒犯或针对私人个体？

内置场景及回应虚构；不预测真人心理，不冒充群友。发送者标签不进入模型请求，但正文仍可能识别人，使用者须有权用于该模型。

## 7. 建议审核路线？

**human-review。** 0.5.4 经 GitHub 发布流程发布（标签 v0.5.4）。应用代码与 0.5.3（标签 v0.5.3，提交 c6caef3）相同，0.5.4 只更新商店截图与介绍文字。重点核对目标/修订的实际效果、发送两步确认与回读核验的实际表现、宿主数据范围、重新打开与删除、失败时草稿是否保留。队外用户试用和真实模型质量不能用受控VM测试代替。

新草稿按账号/房间隔离，最多10个记录、每稿8000字节、文件512 KiB；旧版主稿/A/B手动复制与独立删除。没有自动备份、跨进程锁或崩溃原子性保证。第三方模型历史不属于本地删除范围。完整说明见[数据说明](../oncue/PRIVACY.md)。
